# 機械スキャンの弱シグナルを文脈で判断する

スキャンは該当語の位置を示し、違反を断定しない。`[弱]` が付く語には、正当な用法が確認された語と、
正当用法を削らせないため暫定的に弱として扱う語がある。検出 0 件や辞書の同義語への言い換えは、
文書の改善を保証しない。出所の文書を開かずに、該当する文と前後の文で次を判断する。

## 万能語

具体的な対象・値・手順で同じ意味を示せるなら置き換える。ただし、直後に具体例が並ぶ列挙の要約や、
読者の環境によって値が異なる指示まで一律に削らない。指示の対象や決め方が不明なら、その不足を指摘する。

| 架空の例 | 判断 |
|---|---|
| さまざまな形式を扱います。CSV と JSON を入力できます。 | 要約の後に対象が明記されている。万能語だけを理由に違反としない |
| 保管期間には、自組織の保存規程に従う適切な値を設定します。 | 値が読者環境に依存し、選び方が示されている。固定値を創作しない |
| さまざまな対応で処理を最適化しました。 | 対象・変更・観測結果が分からない。それらを求め、未知の数値は作らない |

## ヘッジ

原因と条件が特定された外部事象の不確実性を、書き手が決定や根拠の説明を避ける留保と区別する。
原因・条件・対象が、その文か前後の文から特定できることを確認する。外部事象が確率的であることと、
書き手がその確率を測っていることも区別する。裏付けのない確率や断定を足さない。

| 架空の例 | 判断 |
|---|---|
| 接続が切れた場合、確認済みの項目だけが保存される可能性があります。未確認の項目は再送します。 | 接続断という条件と保存対象が明記されている。事実的不確実性として残せる |
| 更新は明日行うべきだと思われます。総合的に判断することが重要です。 | 書き手の判断と根拠が示されていない。結論と理由を求める |
| 改善する可能性があります。 | 何が、どの条件で変わるか不明。情報を求め、測っていない改善を断定に変えない |

## その他の弱シグナルと強シグナル

前置き語が、段落を遅らせる挨拶か、対象を示す必要な文かを読む。
「正面から」「多角的」「掘り下げる」「開かれた問い」「議論を運ぶ」の検出も一律禁止にせず、
具体的な説明に寄与しているかを判断する。該当がなかったことは正当用法の証明ではない。
記号表記は共有の `tech-write/references/style.md` に従い、引用・コード・表・URL の用法と区別する。

強シグナルの基準、留保の回数、文体レジスタの例外、修正の最大回数は各スキルの規定を変えない。
原文にない値・日付・主体・原因を修正案に足さず、必要な情報は【要確認: 何が必要か】で示す。
references へ渡される規範・スキルのディレクトリは呼出し元が解決したパスであり、ここで
プラグイン用変数の置換や現在の作業場所からの探索を行わない。

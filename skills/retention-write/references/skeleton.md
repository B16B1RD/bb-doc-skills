# 執筆テンプレートと型

## 文体レジスタ——断定と威圧を分ける

ここが文体レジスタの規定の本体である。原則集・retention-write/retention-review の各ファイルはこの節を参照し、規定を重複して定義しない。

断定は内容の性質であり、文体は読者との関係の関数である。決定・理由・却下は明確に断定したまま、語り口は中立に保つ。詠嘆や読者への指示形は、書き手が読者の上位にある文書（経営層からの指示・訓示）や私的な文章（個人ブログ）でだけ選べる。同格・上位・社外の読者に向けたビジネス文書で使うと、慣習に反して内容ではなく文体が記憶に残る。判断に迷ったら音読し、同僚や上長にそのまま出して違和感がないかで決める。

レジスタは独立した 2 軸で決まる。軸 1 は敬体（です・ます調）か常体（である調）か、軸 2 は中立か詠嘆・指示かである。**既定は敬体 × 中立**。上書き規則が動かすのは軸 1 だけである。軸 2 の中立が外れるのは読者が部下の指示文書と私的な文章に限り（本節末尾を参照）、それ以外ではどちらの文体でも動かさない。敬体は指示・勧誘の語形が自然に読めるぶん軸 2 の逸脱に気づきにくいので、下表の左列を具体形で覚える。

| 軸 1 文体 | 軸 2 詠嘆・指示のレジスタ（使わない） | 軸 2 中立のレジスタ（既定） |
|---|---|---|
| 敬体（既定） | 目的は〜。それだけです。 | 目的は〜の一点です。 |
| 敬体（既定） | 倉庫を思い浮かべてください。 | 倉庫にたとえると構造が見えやすくなります。 |
| 敬体（既定） | まずは実測から始めましょう。 | まず実測から始めます。 |
| 敬体（既定） | ここで予想してください——毎分何件でしょうか。数字を置いてから次を読んでください。 | ここで一問——ピーク時の発行要求は毎分何件でしょうか。（問いだけを置き、指示文を重ねない） |
| 敬体（既定） | この構成なら移行しても安全ですよね。 | この構成では不整合が起きません。 |
| 常体（上書き時） | 〜を二度と起こせない構造にするからだ。 | 〜を二度と起こせない構造にするためである。 |
| 常体（上書き時） | 目的は〜。それだけだ。 | 目的は〜の一点である。 |
| 常体（上書き時） | 倉庫を思い浮かべてほしい。 | 倉庫にたとえると構造が見えやすい。 |
| 常体（上書き時） | この文書に戻ってきてほしい。 | この文書に立ち返る。 |

常体そのものは違反ではない。上書き規則で常体を選んだ文書を、文体だけを理由に直させない。指摘の対象は左列——敬体か常体かによらず詠嘆・指示の語形である。

軸 1 で対になる語形が、軸 2 で対になるとは限らない。常体の「〜からだ。」が詠嘆になるのは である調の中立形が「〜ためである。」だからで、敬体では「理由は X だからです。」が中立の標準形にあたる。表の左列に敬体の「〜からです。」を置かないのはこのためで、`scan.py` の `STYLE_REGISTER_MARKERS` も同じ理由で当該語形を持たない。

### 上書き規則

既定（敬体）を上書きするのは次の 2 つだけで、優先順位は上が強い。

1. 明示キーワード——指示文に「である調で」「常体で」「だ・である調で」があれば常体で書く。「です・ます調で」「敬体で」があれば敬体で書く
2. 既存文書からの継承——既存文書への追記・部分改訂では、その文書の文体をそのまま継ぐ。常体の設計メモに節を足すなら常体で書き、同一文書内で文体を混ぜない

どちらにも当てはまらなければ敬体で書く。文書の種別（ADR・設計メモ・障害報告）からは既定を推定しない——種別判定を外すと文体も外れるため、分岐そのものを持たない。

読者が誰かはインテーク 2 問目で確定する。その回答が「部下への指示」のとき、および私的な文章を書くときだけ、詠嘆・指示レジスタも選択肢に入る——それは軸 2 の例外であって既定ではない。

## 判断文書のスケルトン

1. 賭け金（第一段落）——「X する。完了は◯月末、責任者は◯◯。理由は……である。」見出しも結論を含む形に（「〜の検討について」ではなく「X を Y に移行する」）
2. 何が起きたか（因果の物語）——起点の出来事を時刻・主体・因果連鎖で。「課題が 3 つあります」型の列挙に逃げない
3. スキーマフック——中核主張と構造が同型の比喩を 1 本。新しい・難しい主張の直前に置く
4. 検証・性能などの山場——直前に生成の問い（「ここで一問——◯◯は毎分何件でしょうか。」常体なら「〜だろうか。」。問いだけを置き、指示文を重ねない）。答えは折りたたみ（`<details>`）か次の節に置く
5. 検討して捨てた案——各 1〜2 文 + 「却下。」
6. 留保——一度だけ。再検討の条件を specific に（「◯◯が△△を超えたら再検討」）
7. 強調——文書全体で 1 箇所。「1 週間後に残す一文」を選んで太字にする
8. 読了チェック——「◯◯チェック — 1 週間後の自分に」として 3 問

節の順序は入れ替えてよいが、賭け金が先頭・読了チェックが末尾なのは固定。

## 賭け金の型

立場（何をする・何を主張する）＋期限＋責任者＋理由一つ。書けない要素は無理に作らない（期限のない考察記事なら立場と理由だけ）。ただし立場の断定は必ず——「〜を検討する」は賭け金ではない。

## 想起 3 問の型

1. 中核のメカニズム・理由を問う（「なぜ X が起きたのか」「なぜ Y でなければならないのか」）
2. 却下案がなぜだめかを問う（「なぜ Z 案では解決しないのか」）
3. 再検討・行動の条件を問う（「どうなったらこの判断を見直すか」「読者は次に何をすべきか」）

用語の穴埋めのような些末な問いにしない。3 問に答えられれば文書の中核が再生できる、という基準で選ぶ。

## 連絡メモのテンプレ（軽量モード）

- 1 文目 = 決定・依頼の結論。「お疲れさまです」「〜について共有します」で始めない
- 続く 2〜4 文 = 理由と具体（数字・日付・対象）
- 最後 = 読者が取るべき行動と期限
- 使わないもの：比喩・クイズ・生成の問い・想起テスト・「〜ればと思います」「〜が望ましいと考えられます」型のヘッジ
- 長さの目安：10 行以内。それを超えるなら判断文書として書くべき内容が混ざっていないか疑う

## 納品前チェック対照表（scan.py が使えないとき）

弱シグナルの正当用法と空疎な表現の区別は、呼出し元が実体から解決した
`retention-review/references/scan-guidance.md` に従う。目視でも弱シグナルを一律に禁止せず、
以下の強シグナルの基準と区別する。

| 確認項目 | 基準 |
|---|---|
| 前置き・社交フィラー（本ドキュメントでは／お疲れさまです） | 0 |
| 死んだ比喩（車の両輪・銀の弾丸） | 0 |
| 万能語（最適化・効率化・柔軟に・様々な） | 実測値・固有名に置換済み、またはその語を含む文ごと削除済み（引用内は除く。別の語への言い換えは解消と数えない） |
| ヘッジ（可能性があります・と考えられます・ればと思います） | 留保節の 1 回だけ（別の語への言い換えは解消と数えない） |
| 強調（太字・囲み） | 1 箇所以下 |
| 読了チェック 3 問 | 判断文書には必須／連絡メモには付けない |
| 生成の問い | 判断文書に 1 つ以上／連絡メモには不要 |
| 文体レジスタ（文体レジスタ節の 2 軸表の左列の語形） | 0（部下への指示文書・私的な文章を除く） |
| 数字 | 提供された実数のみ。創作した数値が 1 つもない |

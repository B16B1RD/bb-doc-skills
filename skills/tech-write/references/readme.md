# README / OSS 入口文書の原則

README の読者は「評価して、使い始めたい」人。読むのではなくスキャンし、滞在時間は数十秒〜数分。
この読者に対する README の仕事は 3 つ — (1) 何であるか即答する (2) 使い始めまでの最短路を示す
(3) 詳細への案内板になる。

## 原則

### R1. 30 秒ルール（逆ピラミッド）

最初の 1 画面（タイトルから見出し 2 つ分）で what（何か）／why（なぜ使うか）／how（どう始めるか）に
到達できること。

- 検査：冒頭 30 行だけを読み、プロダクトの一行説明・主要な利点・インストールコマンド（または
  そこへのリンク）が見つかるか。

### R2. 型に従う

OSS README には読者が期待する節順がある：
タイトル／バッジ → 一行説明 → デモ → why → インストール → クイックスタート → 使い方（コマンド等）→
設定 → ドキュメントへのリンク → ライセンス。
独自構成は読者のスキャンを壊す。節を増やすより docs/ へ逃がす。
この型は順序の期待であって網羅列挙ではない。Uninstallation・Troubleshooting・Contributing 等の
追加節は、対応する位置（使い方の後・ライセンスの前後）に置かれていれば型準拠とみなす。

- 検査：期待順から外れた節はないか。README にしか書かれていない詳細情報はないか。

### R3. 1 つの事実は 1 箇所（README は案内板）

仕様の詳細は docs/（SPEC、CONFIGURATION 等）で管理する。README には要約 1〜2 行 + リンクだけを置く。
README に仕様詳細を書くと、変更のたびに複数箇所の同期が必要になり、必ず乖離する。

- 兆候：フラグ名・内部カウンタ・エッジケース挙動・内部ファイルパスの列挙が README 本文にある
  （changelog 由来の追記が堆積した状態）。
- 検査：各節について「この詳細は docs 側で管理されているか。README に詳細が堆積していないか」を問う。

### R4. Features は 1 項目 1〜2 行

各項目 = 何ができるか + 何が嬉しいか。それを超えた項目は仕様詳細が漏れ込んでいる。
詳細は docs へ退避し、README にはリンクを残す。

- 検査：分量は物理行数ではなく情報量で判定する（ソース 1 行に詰めても不合格）。目安は
  描画後 3 行 — 日本語なら約 150 字、英語なら約 300 characters。超えた bullet を列挙する。

### R5. コード例はコピペで動く最小形

前提条件（要インストール等）は例の直前に 1 行で書く。動かない例・省略記号入りの例は載せない。

- 検査：各コードブロックを「初見の人がそのまま実行できるか」で判定する。

### R6. 英日ペア同期

対訳 README は構造（見出し・順序・表の行数）を一致させ、内容を等価にする（逐語訳は不要）。
片方だけの更新は乖離事故のはじまり。

- 検査：見出しリストを両言語で並べて突き合わせる。表の行数・リンク先も比較する。

### R7. 文体

`style.md` の検出リストを全文に適用する。README では特に万能語（why 節）と太字乱発（Features 節）が
出やすい。日本語文書の敬体／常体は `style.md` の S8 に、記号は S9 に従う。

### R8. 事実との突き合わせ

README は最初に古びる文書。記載と実体の乖離は読者の信頼を一度で壊す。

- 検査：相対リンク・参照ファイルパスが実在するか。バージョンバッジがパッケージメタデータ
  （plugin.json、package.json 等）と一致するか。記載コマンド・設定キーが現行実装に存在するか。

## 執筆プロセス

1. 詳細の置き場の確認 — docs/ に仕様の詳細があるか確認する。README に詳細が堆積していれば、
   docs へ移す提案を成果物に含める。
2. 骨格を R2 の型で組む。
3. 各節を原則に従って書く（Features は R4、コード例は R5）。
4. style.md で全文を走査する。
5. 英日ペアなら両方を同時に更新する（R6）。

## レビューチェックリスト（tech-review 用）

- [ ] R1: 冒頭 30 行で what/why/how に到達できるか
- [ ] R2: 節順が型から外れていないか
- [ ] R3: docs で管理すべき詳細が README に堆積していないか
- [ ] R4: 情報量が目安（描画後 3 行）を超える Features 項目はないか
- [ ] R5: コピペで動かないコード例はないか
- [ ] R6: 英日ペアの構造・内容は同期しているか
- [ ] R7: style.md の検出リスト（S8・S9 を含む）に引っかかる箇所はないか
- [ ] R8: リンク・バージョン・コマンド名が実体と一致しているか

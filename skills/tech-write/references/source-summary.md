# 原典の紹介の原則

原典の紹介は、他人の論文・技術記事を、書き手の主張を足さずに要約して伝える文書である。読者は
「原典を読む前に、何がどの条件で示されたかを正確に知りたい」。紹介文の数値や条件が原文とずれると、
読者は原典を開かないまま誤った理解を持ち帰る。そのため、この種別では書き方より先に、原典を読んで
照合する手順を定める。

## 対象の見分け方

依頼の目的が「原典の内容を伝えること」なら、この種別にする。「この論文を紹介して」「この記事を要約して」
「論文の要点をまとめて」が該当する。「この記事を紹介するブログ記事を書いて」のように、意見や感想を書くかを
指定しない紹介ブログ記事も、この種別に含める。ブログという投稿先は、書き手の主張を足す理由にならない。

- 書き手の意見・評価・推奨を加える依頼（「紹介して、自分の意見も書いて」「この論文を根拠に提案を書いて」）は、
  主張文書として retention-write に切り替える。紹介と主張の両方を求める依頼も、主張を含む時点で切り替えを伝える
- 論文・記事やトピックを絵や図解で説明する依頼（「この論文の要点を初心者向けに絵で説明して」など）は explain の担当にする
- 原典を別の言語へ訳す依頼は翻訳であり、この種別では扱わない

## 原則

### O1. 原典を全文読んでから書く

要約・抜粋・検索で拾った一部から紹介文を書かない。PDF は全ページを読み、ページ数と読めたページを控える。

- 原典を取得できない（URL が 403 を返す、PDF が壊れている）ときは、読めなかったことと失敗した操作を報告し、
  要約の本文を出さない。タイトルや抄録の断片から内容を推測して書かない
- 一部だけ読めたときは、読めた範囲（例：1〜8 ページ、3 節まで）を本文と納品報告の両方に書き、
  読めなかった範囲に関わる内容は【要確認：読めなかった範囲の内容】で残す
- 検査：納品報告に、読んだ範囲と読めなかった範囲（なければ「なし」）が書かれているか。

### O2. 書き手の主張を足さない

紹介文の断定は、原典の著者が述べたことに限る。「画期的」「実務で使える」のような書き手の評価、原典が
試していない条件への一般化、原典にない推奨を足さない。著者の主張は著者に帰属させる（「著者らは〜と述べている」）。

- 悪い例：「この手法を使えば、どの言語モデルでも推論が速くなる」（原典は 2 つのモデルで測っただけ）
- 良い例：「著者らは 2 つのモデルで、推論時間が 30% 短くなったと報告している」
- 検査：各断定に、原典の対応箇所を示せるか。示せない文は削るか、原典の記述に戻す。

### O3. 数値・条件・限界を原文と照合する

数値は値・単位・比較対象・測定条件（データセット、設定、対象）を組で写す。丸めは原文の桁に合わせ、
割合と差分、相対値と絶対値を入れ替えない。条件を外した数値は、別の主張になる。

- 検査：本文の数値ごとに、原典の位置（節・ページ・表番号）と値が一致するか。条件が数値の近くに書かれているか。

### O4. 引用は判断に必要な最小限にとどめ、`>` で区別する

原文の引用は、読者が要約の正しさを判断するのに要る箇所だけにする。引用は `>` の行に置いて要約の文と区別し、
原典の位置（節・ページ）を添える。段落や節をまるごと転載しない。

- 検査：引用が `>` の行だけにあり、各引用に位置があるか。引用を除いても紹介文として読めるか。

### O5. 出典を必ず書く

原典のタイトルと URL を必ず書く。著者名と公開年が原典にあれば添える。URL がない資料は、取得元
（書誌情報、ファイル名）を書く。

- 検査：出典のタイトルと URL（または取得元）があるか。

### O6. 図表は転載せず、位置だけを示す

原典の図表は画像・表ともに転載しない。「論文の Figure 3」「表 2」のように位置を示し、必要なら図表が
示す内容を文で要約する。図表から読み取った数値も O3 の照合に掛ける。

- 検査：原典の図表をそのまま写した画像・表がないか。図表への言及に位置があるか。

### O7. 原典の限界を省かない

評価した範囲（データセット・規模・対象）、検証していない条件、著者が挙げた限界を、成果と同じ紹介文の中に書く。
成果だけを並べると、読者は原典が示していない範囲まで成り立つと読む。限界を原典が書いていなければ、
書いていないことを書き、書き手が限界を推測して足さない。

- 検査：評価の範囲と、著者が挙げた限界が本文にあるか。

## 執筆プロセス

1. 依頼を確かめる — 主張・評価・推奨を求める部分があれば retention-write への切り替えを伝え、
   この種別では書かない。
2. 原典を取得して全文読む（O1）。PDF はページ数を確かめ、全ページを読む。取得できなければ報告して止める。
3. 原典から、目的・手法・結果の数値と条件・限界を抜き出し、それぞれの位置（節・ページ・表番号）を控える。
4. 紹介文を書く。冒頭で、原典が何を示したかを 1〜2 文で述べ、続けて条件・数値・限界を置く。
   出典（O5）を書き、引用は O4、図表は O6 に従う。
5. 照合する — 本文の各断定と数値を控えた位置と突き合わせる（O2・O3）。足した評価・一般化を除く。
6. 納品報告に、読んだ範囲（例：全 12 ページ）と読めなかった範囲、引用した箇所の位置を書く。

## レビューチェックリスト（tech-review 用）

監査では、紹介文と一緒に原典も読む。原典を取得できないときは、O2・O3・O7 を「原典未確認」として報告し、
原典と照合しないまま食い違いの有無を判定しない。

- [ ] O1：読めなかった範囲の内容を推測で書いていないか。一部だけ読んだ紹介文なら、読めた範囲が本文に示されているか。納品報告も渡されていれば、読んだ範囲と読めなかった範囲が書かれているか
- [ ] O2：原典にない評価・一般化・推奨を足していないか。著者の主張が著者に帰属しているか
- [ ] O3：数値の値・単位・比較対象・条件が原文と一致するか
- [ ] O4：引用が `>` の行で区別され、最小限で、位置があるか
- [ ] O5：出典のタイトルと URL（または取得元）があるか
- [ ] O6：図表を転載せず、位置を示しているか
- [ ] O7：評価の範囲と著者が挙げた限界を省いていないか
- [ ] style.md S8：日本語の敬体／常体が規定どおりか
- [ ] style.md S9：日本語の記号が規定どおりか

# Issue コメント／PR コメントの原則

コメントの読者も 2 人いる — 「通知でこのコメントだけを読む参加者」と「後からスレッド全体を
流し読みする調査者」。前者はコメント単体で用件が分かることを、後者はスレッドを全部読まずに
結論だけ拾えることを求める。

## 原則

### C1. 第一文で用件を宣言する

通知メールやモバイルでは冒頭しか見えない。最初の 1 文で、これが報告・質問・決定・返信の
どれで、何についてかが分かること。

- 良い例：「原因を特定しました。`parse_csv()` が BOM 付き UTF-8 を想定していません」
- 悪い例：「調べてみたところ、いくつか分かったことがあるので共有します」（S1 前置きフィラー）
- 検査：第一文だけ読んで、続きを読むべきか判断できるか。

### C2. 返信対象を明示する

スレッドでは複数の話題が交錯する。何に応答しているかを引用（`>`）やコメントへの個別リンクで
示す。ただし引用は判断に必要な最小限にとどめ、相手のコメント全文を再掲しない。

- 検査：このコメントだけ読んで、どの発言・指摘への応答か分かるか。

### C3. 事実と解釈を分離する

調査報告では、観測した事実（実行したコマンド、ログ、出力の原文）と、そこから導いた解釈・仮説を
分けて書く。事実はコードブロックで原文を、コードの参照は permalink（コミット SHA 付き行リンク）で
示す。ブランチ参照の行リンクは後の変更で行がずれて死ぬ。

- 検査：読者が事実だけを見て、書き手と別の解釈を立てられる状態か。

### C4. レビュー返信は指摘ごとに決着をつける

指摘 1 件ごとに「対応した（修正コミットへのリンク）／対応しない（理由）／別 Issue 化（リンク）」の
いずれかを明示する。まとめて「直しました」だけの返信は、どの指摘がどうなったかの照合作業を
レビュアーに丸ごと返している。

- 検査：各指摘の行き先が 3 択のどれかで示されているか。

### C5. 質問は回答可能な形にする

試したこと・現状の理解を先に書き、判断してほしい点を選択肢つきで問う。オープンな
「どう思いますか?」は構造化の作業を相手に転嫁している。

- 良い例：「A 案（後方互換を保つ）と B 案（破壊的変更で単純化）のどちらで進めますか。実装コストは A が +2 日です」
- 検査：相手が 1 往復で答えられる形になっているか。

### C6. 結論はコメントに埋葬しない

スレッドで決まったこと・クローズ理由を、全コメントを読まないと分からない状態にしない。
決定は Issue 本文（冒頭や完了条件）への反映を提案するか、クローズコメントに
「結論 + 対応 PR/コミットのリンク」を自己完結で書く。「Fixed」だけのクローズは
数ヶ月後の検索者に何も伝えない。

- 検査：この Issue/PR を検索で見つけた人が、本文と最後のコメントだけで顛末を把握できるか。

## issue.md との関係

コメントで新しいバグ報告や機能要望を始めない。それは別 Issue に起票して本スレッドからリンクする
（issue.md の I5 と同じ理由 — コメントに埋まった報告は追跡できない）。既存 Issue への再現報告・
追加情報はコメントでよい。

## 執筆プロセス

1. スレッドを読む — 対象 Issue/PR の本文と先行コメントを取得する
   （`gh issue view <n> --comments` / `gh pr view <n> --comments`）。C2 の返信対象の特定と
   既出情報との重複回避は、スレッドを読まずにはできない。
2. コメントの用件（報告／質問／決定／返信）を 1 つに定める。複数あるなら分けるか、
   見出し・箇条書きで区分する。
3. C1 の第一文を先に書く。
4. 用件に応じて本文を組む — 返信なら C2 + C4、調査報告なら C3、質問なら C5、
   決定・クローズなら C6。
5. style.md で走査する（コメントでは前置きフィラーと過剰ヘッジが特に出やすい）。日本語の敬体／常体は
   S8 に、記号は S9 に従う。

## レビューチェックリスト（tech-review 用）

- [ ] C1: 第一文だけで用件が分かるか
- [ ] C2: 返信対象が明示されているか（引用・リンク）
- [ ] C3: 事実と解釈が分離され、事実は原文・permalink で示されているか
- [ ] C4: レビュー指摘ごとに決着（対応／見送り／別 Issue）が明示されているか
- [ ] C5: 質問が回答可能な形（現状の理解 + 選択肢）になっているか
- [ ] C6: 決定・クローズ理由が自己完結し、本文への反映が考慮されているか
- [ ] style.md S8: 日本語コメントの敬体／常体が規定どおりか
- [ ] style.md S9: 日本語コメントの記号が規定どおりか

# 投稿先：X Articles

X Articles は、X の上で見出しや画像を含む長い記事を書く機能で、X の短文の投稿（長文投稿を含む）とは別である。
X の短文の制約（`references/channels/x.md`）はこの投稿先には当てない。
読者は、タイムラインに出た記事のカードからタイトルと冒頭を見て、開くかどうかを決める。
タイトルと冒頭の段落で、記事の結論と読者が得るものを示す。

## 確かめた仕様

次の 4 つは、X Articles のエディタで確かめた仕様である（2026 年 11 月時点）。この値をそのまま使い、【要確認】にしない。

| 項目 | 仕様 |
|------|------|
| タイトルの文字数 | 100 文字以内 |
| ヘッダー画像の縦横比 | 5:2 が最良 |
| Markdown をエディタに貼ったとき | 書式にならない |
| Markdown をエディタに直接入力したとき | 書式になる |

貼った Markdown は書式にならないので、書式は、利用者が貼った後に手で直す。
手で直すときに Markdown のほうが扱いやすいので、記事は Markdown で納品する（下の「納品の形」）。
直接入力でどの記法が書式になるかは確かめていない（下の表の「記法の対応範囲」）。

## 公式に確定できない仕様

公式のヘルプの記述が食い違うか、確かめられていないために、確定できない仕様がある。規範に値を固定せず、
納品報告で、次の項目を【要確認】の一覧として示し、利用者が投稿前に確かめる範囲を分かるようにする。記事の本文がこれらの項目に触れるときも、値を断定せず、その箇所を【要確認】で残す。
この表の項目には、推測の値を書かない。利用者が確かめた値を依頼で示したときだけ、その値を使う。

| 項目 | 扱い |
|------|------|
| 書けるプラン | 【要確認：記事を書けるプランと、利用者のアカウントで書けるか】 |
| 記法の対応範囲 | 【要確認：見出し・太字・斜体・箇条書き・引用・コード・表・埋め込みのうち、エディタが対応するもの】 |
| 本文の文字数の上限 | 【要確認：本文の文字数の上限】 |
| タイトルの文字数の数え方 | 【要確認：タイトルの 100 文字は、全角の文字を 1 と数えるか、2 と数えるか】 |
| 画像・動画の上限 | 【要確認：添付できる画像・動画の数とサイズの上限】 |

稿が長くなる見込みのときは、本文の上限が未確認であることを納品報告に書き、
利用者が下書きに貼って入りきるか確かめるよう案内する。

## 納品の形

- 記事は Markdown で書く。1 行目に `# ` の見出しでタイトルを書き、本文の見出しは `##` から始める。太字・箇条書き・引用・リンク・コードも Markdown の記法で書く
- タイトルは 100 文字以内にする。文字数は目視でなく、下の「タイトルの文字数」のコマンドで数え、数を納品報告に書く。100 文字を超えたら、収まるまで縮めて数え直す
- 画像の位置は「［画像：何の画像か］」の 1 行で示す
- 記事の Markdown は、ファイルに保存して渡すか、全体を 1 つのコードブロックに入れて示す。記号が表示のときに書式に変わると、利用者に Markdown が届かないためである。記事の中にコードブロックがあるときは、外側のフェンスを内側より長くする
- 【要確認】の一覧は納品報告に書き、記事の Markdown には入れない
- 納品報告には、次の 2 つも 1 文ずつ書く。貼った Markdown は書式にならないので、貼った後に書式を手で直すこと。ヘッダー画像を付けるなら、縦横比は 5:2 が最良であること
- 投稿本文は HTML にしない。依頼が「HTML で」と明示しても、記事は上の Markdown で納品する

## タイトルの文字数

タイトルの文字数は、1 文字を 1 と数える。X の短文の重み付きの数え方（`references/channels/x.md`）は使わない。
X が、タイトルでも全角の文字を 2 と数えるかは確かめていない（上の表の「タイトルの文字数の数え方」）。
1 行目がタイトルのファイルを渡す。記事のファイルをそのまま渡してよい。行頭の `# ` は数えない。

```bash
python3 -c 'import sys; print(len(open(sys.argv[1], encoding="utf-8").readline().strip().removeprefix("# ")))' <1 行目がタイトルのファイル>
```

## 読者の前提の例

文脈を持たない読み手に渡す「読者の前提」は、次の例から依頼に合うものを選ぶ。

- タイムラインに出た記事のカードで、タイトルと冒頭だけを見て開くかどうかを決める人
- 書き手をフォローしているが、その分野の専門用語は知らない人
- 記事を開いたが、見出しだけを拾い読みして要点を知りたい人

# 投稿先：X Articles

X Articles は、X の上で見出しや画像を含む長い記事を書く機能で、X の短文の投稿（長文投稿を含む）とは別である。
X の短文の制約（`references/channels/x.md`）はこの投稿先には当てない。
読者は、タイムラインに出た記事のカードからタイトルと冒頭を見て、開くかどうかを決める。
タイトルと冒頭の段落で、記事の結論と読者が得るものを示す。

## 公式に確定できない仕様

公式のヘルプでも記述が食い違い、確定できない仕様がある。規範に値を固定せず、
稿と納品報告では次の項目を【要確認】として示し、利用者が投稿前に確かめる範囲を分かるようにする。
推測の値を書かない。利用者が確かめた値を依頼で示したときだけ、その値を使う。

| 項目 | 扱い |
|------|------|
| 書けるプラン | 【要確認：記事を書けるプランと、利用者のアカウントで書けるか】 |
| 記法の対応範囲 | 【要確認：見出し・太字・斜体・箇条書き・引用・コード・表・埋め込みのうち、エディタが対応するもの】 |
| 文字数の上限 | 【要確認：本文とタイトルの文字数の上限】 |
| 画像・動画の上限 | 【要確認：添付できる画像・動画の数とサイズの上限】 |

稿が長くなる見込みのときは、上限が未確認であることを納品報告に書き、
利用者が下書きに貼って入りきるか確かめるよう案内する。

## 貼り付けたときの扱い

エディタに Markdown や HTML を貼ったときの崩れ方は、実機確認待ちである。
【要確認：Markdown の見本と HTML の見本を下書き（非公開）に貼ったときに、どの書式が残り、どれが記号のまま残るか】。
確認の結果が出るまでは、次の納品の形を使う。

## 納品の形

- 本文は、記号を使わない平文の段落で書く。見出しにしたい行は独立した 1 行にし、`#` などの記号を付けない
- 見出し・太字・箇条書き・リンクなど、エディタの書式で付けるものは、本文とは別の一覧（「エディタで付ける書式」）に、行と書式の組で示す
- リンクは URL をそのまま書く。画像の位置は「［画像：何の画像か］」の 1 行で示す
- 冒頭に【要確認】の一覧を置き、利用者が投稿前に確かめる項目を示す
- 投稿本文は HTML にしない。依頼が「HTML で」と明示しても、記事の本文は上の平文で納品する

## 読者の前提の例

文脈を持たない読み手に渡す「読者の前提」は、次の例から依頼に合うものを選ぶ。

- タイムラインに出た記事のカードで、タイトルと冒頭だけを見て開くかどうかを決める人
- 書き手をフォローしているが、その分野の専門用語は知らない人
- 記事を開いたが、見出しだけを拾い読みして要点を知りたい人

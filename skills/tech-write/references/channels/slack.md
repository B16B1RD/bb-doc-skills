# 投稿先：Slack

Slack のメッセージの読者は、チャンネルの通知や未読の一覧でメッセージの冒頭だけを見て、
自分に関係があるか、何かする必要があるかを決める。用件・期限・読者にしてほしいことを冒頭に置く。
この投稿先の制約は、種別の原則（告知・進捗・質問などの用件は `references/comment.md`）に重ねて適用する。
種別の原則は変えない。

前提：利用者の環境で「マークアップでメッセージを書式設定する」がオンになっていて、
貼って送ると mrkdwn が書式になる。オフの環境では記号のまま表示されるので、利用者が設定を確かめる。

## mrkdwn の記法

Slack は標準 Markdown と違う mrkdwn という記法を使う。稿は mrkdwn で書き、標準 Markdown の記法を残さない。

| 書式 | mrkdwn で書く | 標準 Markdown で書かない |
|------|---------------|--------------------------|
| 太字 | `*太字*` | `**太字**` |
| 斜体 | `_斜体_` | `*斜体*` |
| 取り消し線 | `~取り消し~` | `~~取り消し~~` |
| リンク | URL をそのまま書く。文字にリンクを付ける記法は表の下に書く | `[text](url)` |
| 見出し | 見出しの記法はない。見出しにしたい行は `*太字*` の 1 行にする | `#`・`##` で始まる見出し |
| 箇条書き | 行頭に `•` か `-` を置いた平文の行 | 入れ子の箇条書き |
| コード | `` `code` ``、複数行は 3 つのバッククォートの行で囲む | 言語名つきのコードフェンス |
| 引用 | 行頭の `>` | 同じ |

- 日本語の文字に直に続く `*`・`_`・`~` は書式にならないことがあるので、書式の記号の前後に半角スペースを置く
- 文字にリンクを付ける mrkdwn の記法は `<https://example.com|文字>` だが、メッセージ欄に貼って送ったときに文字のリンクになるかは【要確認：利用者の Slack で貼って送ったときの表示】。利用者が求めない限り URL をそのまま書く
- 表は書式にならないので、同じ属性の並びは項目ごとの行に書く

## 納品前の確認

納品前に、稿に標準 Markdown の記法が残っていないことを確かめる。
次の 3 つが 0 件になるまで直す。コードの中に書いた例は数えない。

- `**` で囲んだ太字
- `[text](url)` の形のリンク（`](` の並び）
- 行頭の `#` で始まる見出し

## スレッド返信

- 長い補足・ログ・手順の詳細は、親メッセージに入れずスレッドの返信に分ける。親メッセージだけで用件と読者の行動が分かるようにする
- スレッドに分けて納品するときは、親メッセージと返信を区切って示す
- 返信をチャンネルにも投稿するかどうかは依頼に従う

## 納品の形

納品物は、メッセージ欄に貼って送るだけで書式が付く mrkdwn の平文にする。
GitHub に載せる Markdown のファイルや HTML にはしない。
メンション（`@here` や特定の人）は、依頼にある場合だけ書く。

納品の例（staging の停止の告知。日時と URL は依頼に書かれた値を使う）：

```text
*staging を停止します* 10/20（月）10:00〜12:00
この間は staging にデプロイできません。急ぎのデプロイは 9:30 までに済ませてください。
手順の変更点： https://example.com/runbook/staging
```

## 読者の前提の例

文脈を持たない読み手に渡す「読者の前提」は、次の例から依頼に合うものを選ぶ。

- 通知のプレビューで冒頭だけを見て、自分に関係があるかを決めるチャンネルの参加者
- 前後のやりとりを読んでいない、別のチームのメンバー
- 後で検索してこのメッセージだけを開いた人

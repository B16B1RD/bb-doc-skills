# explain — 裏取りつきの図解説明

このスキルの中核は絵の巧さではなく順序である。書いてから検証する順では、平易に崩した文が検証可能な形を
していないため裏取りが空振りする。事実リストを先に作り、草稿を渡さない別文脈で裏取りし、そのうえで
絵と文に翻訳する。生成物は上の階（絵 + 一文 + 根拠ピン。連鎖の末尾に着地を 1 つ置いてよい）と下の階
（検証サマリ・凡例・事実リスト・「このたとえ話が壊れるところ」・読了チェック）を持つ自己完結 HTML で、
読者は上の階だけ読んでも、下の階で裏を取ってもよい。

## 同梱資料の解決

起動時に渡されたスキルの場所 `${CLAUDE_SKILL_DIR}` を、次のコマンドで実体のディレクトリに解決する。
この文字列が未置換のホストでは、スキルを読み込んだときに示されたディレクトリを引数に渡す。
現在の作業場所や個人の固定パスから推測しない。

このコマンドだけを単独の Bash 呼出しで実行し、別のコマンドを連結しない。
終了コードと標準出力を確認してから、資料を読む。
終了コードが 0 で、次に示す順の絶対パス 3 行を得たときだけ、その結果を使う。
失敗、出力なし、行数やパスの不一致では「資料の読取未確認」と失敗した操作を報告し、そこで処理を終了する。
失敗後は別の配備・キャッシュ・作業場所を検索せず、パスを組み立てて読み直さない。
起動時に示された場所以外の資料で代用せず、以下の本文処理・監査・生成・納品へ進まない。
停止の報告を補うための入力読取りや一覧取得も行わず、追加の道具を呼び出さずにその応答を終える。

```bash
python3 -c 'from pathlib import Path; import sys; p = Path(sys.argv[1]).resolve(strict=True); print(p); print(p.parent); print(p.parent.parent / "memorable-doc-principles.md")' "${CLAUDE_SKILL_DIR}"
```

出力の順は、このスキルの実体ディレクトリ、5 スキルを含む `skills` ディレクトリ、規範のパスである。
プラグイン配備では規範に `${CLAUDE_PLUGIN_ROOT}/memorable-doc-principles.md` を使い、上の実体起点の
パスと同じルートの 1 部であることを確認する。開発用 symlink 配備では、プラグイン用変数が未置換でも
実体起点の規範パスを使える。規範のコピーをスキルごとに置かない。

参照を解決したら、規範の全文を Read してから以下の手順へ進む。
存在・サイズの確認、検索で抜き出した一部、要約だけでは全文読取の代わりにならない。
一度で取得できなければ分割して末尾まで読み、未回収が残れば読取未確認を報告して停止する。
適用する観点と強度は各スキルの以下の手順に従い、規範を読んだことだけで適用対象を広げない。

本文の `references/` はこのスキルの実体ディレクトリから、兄弟スキルは解決済みの `skills` ディレクトリ
から読む。`<このスキルのディレクトリ>` も同じ実体を指す。Read の前に絶対パスに直し、references や
別の実行者へ必要な参照を渡すときも解決済みのパスを渡す。references の本文や Bash の中で
プラグイン用変数が自動置換されるとは仮定しない。規範や必要な参照を読めなければ検証失敗とし、
要約だけで読取済みにしない。

生成物・原稿・スキャン結果・スクリーンショットは利用者の作業領域に保存する。
スキルの実体、規範、プラグインキャッシュには書き込まない。指定先がそこに含まれる場合も保存せず、
利用者の作業領域の保存先を確認する。読み取る資料のパスを成果物の保存先に流用しない。

## 引数

トピックだけが必須で、残りは自然言語で受ける。`--deep` はその語のまま受け付ける。`--level` のような
フラグは設けない。

| 項目 | 既定値 | 指定時の値 | 指定の形 |
|------|--------|-----------|---------|
| トピック | （必須） | — | 第 1 引数 |
| レベル | 大人（前提知識ゼロ） | 5 歳／小学生／中学生／高校生 | 「中学生向けに」など自然言語 |
| 配布先が知っていること | 空（宣言なし） | 配布先の既知の宣言 | 「HTTP は知っている」「HTTP とブラウザは既知」など自然言語 |
| つまずき点 | 入力なし（推定する） | 配布先が分からないこと | 「なぜ証明書が要るのか分からない」など自然言語 |
| 形 | 題材から 1 つ選ぶ（迷えば一直線） | 一直線／分岐／状態遷移／往復 | 「分岐の形で」など自然言語 |
| 裏取りの件数 | 骨格 claim 最大 5 件 | `--deep` で最大 20 件 | `--deep` |
| 出力先 | ローカル保存のみ | 「Artifact で」でローカル保存に加えて Artifact 公開 | 「Artifact で」 |
| 保存パス | カレントディレクトリ直下 `explain-<slug>.html` | ユーザー指定のパス | 「~/notes/dns.html に」など |
| 出力言語 | 日本語 | ユーザー指定の言語 | 「英語で」など |

トピックの言語には追従しない。技術用語は英語のまま出し、必要なら言い換えを添える。
既知は配布先の知識であり、依頼者本人の知識から推測しない。`--known` のようなフラグは設けない。
宣言が空なら、既知による省略を行わず「前提とした知識」節も出さない。レベルと既知の宣言は別に受ける。
つまずき点も既知とは別に受け、入力がトピックに関係するなら推定で補わない。

## reference の契約

本文は手順と契約だけを持ち、判断の中身は reference に委ねる。各 reference は該当フェーズの開始時に
Read する。

| ファイル | 提供するもの | Read するフェーズ |
|---------|------------|-----------------|
| `references/fact-check.md` | 事実リストの形式、骨格 claim の選び方、手順 3 が定める起動形態に従うための裏取り手順、3 分類の意味 | 事実リスト作成（手順 2）と裏取り（手順 3） |
| `references/simplification.md` | 単純化の許容基準、比喩の扱い、省略の 2 分類、過度一般化の検査、レベル別の 3 つまみ表 | 翻訳（手順 4） |
| `references/page-skeleton.md` | 二層 HTML の骨格、根拠ピン（上の階から事実リストへの参照）の記法、テーマ・CSP の規則、inline SVG の規則、ローカル保存と Artifact 公開の手順 | HTML 生成（手順 5）と保存・公開（手順 7） |

定義の置き場所：裏取り件数は上の引数表、Agent の起動形態は手順 3 の本文で定める。reference はどちらも
再定義しない（reference が書くのは、その規則に従うための手順の中身である）。

裏取りの意味論は rite プラグインの pr-review スキルの references 内にある `fact-check.md` と保管庫 Wiki のものを採るが、
実行時にそれらを Read しない。意味論は `references/fact-check.md` に書き写してあり、このスキルは
単体で動く。

## 手順

7 段を番号順に実行する。**「事実リスト → 裏取り → 翻訳 → HTML」の順序は入れ替えない**（先に書いた
草稿は検証可能な形をしておらず、裏取りが空振りするため）。

1. **日付・開始時刻とパラメータを固定する** — 今日の日付と処理全体の開始時刻を記録し、トピック・
   レベル・配布先が知っていること・つまずき点の入力・形の指定・深さ・出力先を引数の表に従って決める。
   以降の判断はここで固定した入力を使う。形の選択と、不適合な指定からの復帰は手順 2 で行う。
   手順 1 の最初に Bash の `date +%s` などの実時計を呼び、返った開始値と時計の種類・単位を
   利用者の作業領域の一時ファイルへ記録する。この取得時点から手順 7 の保存・公開を終えた時点までを
   全体の所要とし、資料解決前の起動時間や返答の送信時間は含めない。再検査でも開始値を取り直さない。
   道具が使えない・取得に失敗した場合は開始値を推定せず、未計測と理由を記録して本文の処理を続ける。
2. **事実リストを因果の連鎖として作る** — いつ・誰が・何を・どうなったの連鎖で書き、各行に限定条件
   （対象・前提・例外）を持たせる。行の形式・骨格 claim の選び方は
   `references/fact-check.md` を Read して従う（件数は引数表の値を使う）。同 reference の
   「形の選び方」に従って形を 1 つ決め、その形の事実リストを作る。
   「つまずき点の記録」に従い、入力を使うか推定するかを決め、答える行をそろえてから骨格 claim を選ぶ。
3. **別文脈で裏取りする** — 全体とは別に実時計から裏取りの開始値を取得・記録し、**親コンテキストを継承しない新規 Agent を
   起動して**（fork は使わない。fork は事実リストを組み立てた推論過程ごと継承するため別文脈に
   ならない）、事実リストだけを渡す（草稿は渡さない）。
   context7 → WebSearch / WebFetch の順で一次ソースと突き合わせ、
   VERIFIED / CONTRADICTED / UNVERIFIED の 3 分類を返させる。手順は `references/fact-check.md`
   （手順 2 で Read 済みなら再読しない）に従う。コード・CLI の挙動を扱うと判定できるときだけ、
   同 reference の「実行による裏取り」に従って最小例の実行を加える。実行を省いた理由・失敗・
   時間切れは文書照合へ戻し、それだけで状態を決めない。実行工程の累計時間は再依頼・差し戻しにも引き継ぐ。
   返答の判定と根拠が同じ行の断定を支持しているかを、同 reference の親の照合に従って確かめる。
   出典の読取や実行が拒否された場合は、別の道具で同じ操作を迂回しない。
   親の照合を含めて裏取りを終えたら同じ時計で終了値を取得する。再依頼・差し戻しでは最初の開始値を
   保ち、最後の終了値までの差を道具で算出する。この裏取り所要だけを HTML の検証サマリへ渡す。
4. **単純化の許容基準で翻訳する** — 裏取り済みの事実リストを、レベルに応じた語彙・比喩・省略量で
   絵と一文に落とす。許容基準・比喩の扱い・レベル別の 3 つまみは `references/simplification.md` を
   Read して従う。図や文にした後も、各述部がどの事実 No に由来するかを保つ。未検証の行を使うときは、
   図の文字や補足も含め、その述部自体の言い切りを落とす。状態列・根拠ピン・隣の文の留保で代用しない。
   配布先の既知の宣言があれば、同 reference の「配布先の既知による省略」に従い、
   宣言に当たる行を上の階から省く。省いた行は事実リストと裏取りの対象に残し、下の階の
   「前提とした知識」に列挙する。読者が経験しうる出来事として言い切れる行が 1 つあるときは、連鎖の末尾の着地を
   1 文で書く。着地の文体は一文の規則に従う。最後のパネルの言い直しは着地にしない。ふさわしい行が
   無い・根拠が CONTRADICTED・言い直しにしかならないときは着地を書かない。根拠が UNVERIFIED または
   「未検証（上限）」のときは言い切りを落とす。1 ページに 1 つまで。置き場所とピンの記法は手順 5
   の骨格に従う。
5. **二層 HTML を生成する** — 上の階は見出し・パネル・着地（任意）・階段、下の階は検証サマリ・凡例・
   事実リスト・「このたとえ話が壊れるところ」・読了チェック 3 問。既知の宣言があるときだけ、下の階に
   「前提とした知識」を加える。つまずき点は入力と推定を区別して下の階に示し、読了チェックは
   つまずき点から起こす。骨格と CSP・SVG の規則は
   `references/page-skeleton.md` を Read して従う。HTML 草案と、下の「納品報告」で組み立てた返答全文を、
   利用者の作業領域の別々の一時ファイルへ Write する。報告草案の全体所要は「計測中」とし、
   手順 7 を終える前に秒数を埋めない。手順 6 はこの実ファイルを検査する。
   **手順 6 の処置を終えるまで納品報告をしない**。納品用の保存・公開は手順 7 で行う。
6. **内部検査に通す** — 手順 5 で書いた HTML と報告草案を Read し、下の「内部検査」の 2 条件で検査する。
   生成時の記憶や「確認した」という宣言で代用せず、照合した文と処置を一時ファイルへ記録する。
   不合格なら同節の処置に従い、報告草案はこの段階では送信しない。
7. **保存し、指定があれば公開する** — 既定はローカル保存のみ。「Artifact で」の指定があるときだけ
   Artifact ツールでも公開する。保存と公開の手順は `references/page-skeleton.md` に従う。
   保存・公開に合わせて草案の文を変えた場合は、その文も同じ事実状態へ照合してから納品する。
   保存・公開が終わった直後に、手順 1 と同じ時計から全体の終了値を取得し、開始値との差を Bash や
   Python で算出する。原開始値・原終了値・算出結果を一時ファイルへ記録し、その結果だけで報告草案の
   所要を置き換える。頭の中の暗算、生成した例の秒数、裏取りだけの値で代用しない。最後に報告草案の
   全文を読み返し、記録した算出結果と一致することを確かめてから送信する。

## 内部検査

納品前に次の 2 条件を検査する。

- **つながりチェック**：`references/simplification.md` の「形ごとのつながりチェック」に従う
  （手順 4 で Read 済み）。一直線では従来どおり前のパネルの結果が次のパネルの入力になっているかを見る。
  宣言で省いた行は「前提とした知識」を元のつながりに挟み、条件を緩めない。
  そこで埋まらない環があれば連鎖の欠落である。着地があるときは、根拠ピンの `href` が事実リストの行の
  `id` を指していることと、その一文が最後のパネルの言い直しでないことを、この条件の内側で見る。
  着地の条件を 3 つ目の検査としては立てない。
  この条件の内側で、Read した HTML と報告草案に次の照合を行う。
  1. 見出し・本文・箇条書き・表セル・SVG の `text`・`title`・`desc`・`aria-label`・
     caption・補足・読了チェックの問いと回答・報告草案から、事実を述べる文を原文のまま引用する。
     「3 のまま。」のような短い回答や「新しい整数」のように性質を含むラベルも拾う。
     一時ファイルに「場所 / 引用した文 / 事実 No / 状態・限定条件 / 処置」の対応を記録する。
     下の階の事実表と報告の形の理由から先に照合し、それから上の階・図・読了チェックを照合する。
     「全件留保済み」「報告は事実断定なし」のような一括記録で、個々の原文の引用を省かない。
  2. 引用した文ごとに `references/fact-check.md` の結果の扱いを適用する。未検証なら、その述部自体で
     未確認と分かるように直す。たとえば「値を取り出す」は「値を取り出すと考えられる（未確認）」、
     「3 のまま。」は「3 のままと考えられる（未確認）」にする。状態列・根拠ピン・隣の caption・
     aria-label・冒頭の一括留保は、別の文の処置に数えない。由来する事実が無い補足は既存の
     差し戻し手順へ戻し、裏付けのない精度保証や「すべて確認した」などの自己評価は削る。
  3. 処置を HTML と報告草案に反映してから、両ファイルを再び Read する。引用と実ファイルを照合し、
     直す予定だけで完了にしない。未処置の文があれば不合格とする。単なる対象名の「整数」「出力」や
     VERIFIED の文、実際に確認した保存先などの納品情報は弱めない。
  この対応表は内部作業用で、ページや納品報告には含めない。
- **読了チェック 3 問は上の階と宣言した前提だけで答えられる**：宣言があるときは上の階と
  「前提とした知識」だけを読んで 3 問に答え、事実リスト・出典など他の下の階の情報を必要としないことを
  確かめる。宣言が空のときは従来どおり上の階だけで答えられることを検査する。
  着地の内容を問うなら、着地も上の階の情報として扱う
  3 問のうち少なくとも 1 問が、記録したつまずき点への答えを問うことも確かめる。

処置は次のとおり。

- 不合格のときは**上の階を直して再検査する**。問いの側を易しくして通すのではなく、上の階に
  足りない環を足す
- 検査の結果を**ページに表示しない**。検査は納品前の自己点検であり、読者向けの情報ではない
- **2 回連続で不合格**のときは、不合格の理由を納品報告に添えたうえで手順 7 に進む（無限ループに
  しない）

## してはいけないこと

- **事実リストより先に HTML を書かない**。順序を崩すと裏取りが空振りする
- **同一コンテキストで裏取りしない**。Agent には事実リストだけを渡し、草稿は渡さない。草稿を見ながらの
  検証は草稿の誤りをなぞる
- **CONTRADICTED の事実を上の階に載せない**。その環を事実リストから外して上の階を組み直し、再び
  内部検査に通す（骨格 claim が CONTRADICTED だった場合もこの規則に従う）。着地の根拠にも
  CONTRADICTED の行を使わない
- **着地を必須にしない**。ふさわしい行が無いときは省く。空の見出しを残さない
- **新しい漢語の名前を当てない**。既存の一般語か素直な文で言えないかを先に試し、言えるならそちらを
  使う。英語概念に訳語を自作しない

## エラー時

| 状況 | 挙動 |
|------|------|
| トピックが空 | 「何を説明しますか」の 1 問だけ聞く。レベルや出力先は聞かない |
| WebSearch / WebFetch / context7 がすべて使えない | 裏取りを UNVERIFIED で続行し、納品報告に「裏取り不能（道具停止）」を 1 行添える。道具の失敗を CONTRADICTED にしない |
| 実行に要るコマンドが無い | 文書照合に戻し、納品報告に「実行不能（コマンドなし）」を 1 行添える |
| 実行ツールが無い、または一時ディレクトリ外への書込みを sandbox で防げない | 実行せず文書照合に戻し、納品報告に「実行不能（道具なし／隔離を保証できず）」を 1 行添える |
| 実行が失敗した | 後片付けして文書照合に戻し、納品報告に「実行不能（実行失敗）」を 1 行添える |
| 実行が時間の上限に達した | 実行中の処理を止めて後片付けし、その行と未処理の行は文書照合へ戻す。納品報告に「実行を時間の上限で打ち切った」を 1 行添える |
| 実行出力と文書が食い違う | fact-check.md の判定条件を確認し、下の階の検証記録に両方を残す。実行不能や条件違いだけで CONTRADICTED にしない |
| 「Artifact で」指定だが Artifact ツールがない | ローカル保存だけを行い、報告で Artifact 未公開と理由を伝える |
| 指定した形に事実リストが合わない | 一直線に戻し、納品報告に「指定した形が事実リストに合わないため一直線に戻した」を 1 行添える |
| 分岐先の行が CONTRADICTED | fact-check.md の「分岐の道を外す」に従い、その道を上の階から外し、残りの道で組み直して再検査する |
| 状態遷移で到達できない状態がある | つながりチェックの不合格とし、上の階を直して再検査する |
| 骨格 claim が CONTRADICTED | 「してはいけないこと」の CONTRADICTED 規則に従う |
| 内部検査に 2 回連続で不合格 | 「内部検査」の処置に従う |
| 着地にふさわしい行が無い | 着地を省いて階段へ落とす |
| 着地の根拠が CONTRADICTED | 着地を省くか、CONTRADICTED でない別の行に差し替える |
| 既知の宣言が事実リストのどの行にも当たらない | 宣言による省略は行わず、納品報告に「宣言に当たる行なし」を 1 行添える |
| 既知の宣言が全行に当たる | 末尾行（結論）は省かず、上の階にパネルを残す |
| つまずき点に答える行が事実リストに無い | 裏取り前に行を足す。足せないときは納品報告に「つまずき点に答える行を追加できず」を 1 行添える |
| つまずき点の入力がトピックと無関係 | 推定に切り替え、納品報告に「つまずき点の入力がトピックと無関係なため推定に切り替えた」を 1 行添える |

## 納品報告

納品時に次の 1 行を出す。事実リストは HTML の下の階に置き、納品報告では再掲せず、この定型行と以下で必要とする実施状況・形の報告に留める。

```text
裏取り <N> 件中 ✅<a> ⚠️<b> ❓<c>、所要 <s> 秒、保存先 <path>
```

`<N>` は**裏取りを実施した件数**（CONTRADICTED による除外前）。`✅` は VERIFIED、`⚠️` は
CONTRADICTED、`❓` は UNVERIFIED の件数。`<s>` は手順 1 の実開始値と手順 7 の実終了値の差。
秒未満を持つ時計なら差を計算してから整数秒へ切り捨てる。異なる種類・単位の時計を引き算しない。
開始・終了の欠落、非数値、終了が開始より前、計算の失敗では「所要 未計測」とし、次の行に理由を添える。
0 秒で穴埋めしない。有効な実測差が 1 秒未満だった場合の 0 秒とは区別する。原時計の返答を捏造しない。
Artifact に公開したときは URL を続けて示す。手順 3 で記録した開始時刻から測って**裏取りに** 3 分
以上かかったと実測できたときは、既定件数の引き下げを提案してよい。裏取りが未計測なら、
閾値未満とも以上とも判定しない。全体の所要から裏取り所要を推定しない。

道具停止・Artifact 未公開・内部検査の 2 回連続不合格・件数引き下げの提案など添える情報があるときは、
上の定型行の**次の行**に 1 行ずつ足す。

形を自動選択したときは、定型行の次に「形：〈選んだ形〉。理由：〈題材のどの関係を示すためか〉」を
1 行添える。指定が不適合だった場合は、エラー時の復帰報告を添える。

最終返答は、内部検査で読み直した報告草案の全文を使う。保存先など確定した納品情報を埋めたら、
送信する全文を報告草案へ反映して Read し、その文だけを返す。ページの内容の要約・導入文・精度保証・
「すべて言い切りを避けた」などの自己評価を前後に追加しない。
形の理由は、題材に即した表示上の関係と読み順で書く。たとえば「式と結果の対応を左から追えるように」
と書ける。評価・計算・変化などの挙動を理由に使う場合は、納品情報ではなく事実の説明として扱い、
その文も内部検査の対応表へ入れ、状態ごとの処置を終えてから使う。
冒頭の「未検証」は後続の断定の代わりにならない。実際に確認した納品情報はそのまま伝える。
